# 对局伤害面板

## 功能概述

对局结束后，自动在主屏右上角弹出一个置顶小窗，展示本局 10 名玩家对英雄造成的伤害与承受的伤害：

- **造成伤害 / 承受伤害** 两个视图用 TAB 切换（`Pivot` 控件），同一套渲染换数据源
- 每行：英雄头像 + 召唤师 ID + 三色堆叠伤害条（物理红棕 / 魔法蓝 / 真实白）+ 数值 + 团队占比
- 我方 / 敌方分两组，组内按伤害降序；条长以组内最高值为基准
- 本人那一行整行加底色、名字用主题色
- 设置里新增开关「对局伤害面板」，**默认开启**

设计稿（HTML 高保真原型，含深色 / 浅色 / 竞技场三种形态的对照）在 `design-demos/damage-panel/index.html`。

## 实现步骤

1. **勘察既有模式**（本仓库已有大量可复用做法，尽量不新造轮子）：
   - 无边框弹窗直接继承 `OpggWindowBase`（与 OPGG 窗口、大乱斗备选池同一基类，自带 `FluentTitleBar` + Mica）
   - TAB 用 qfluentwidgets 的 `Pivot`
   - 胜负底色用 `NoBorderColorAnimationFrame(type='win'/'lose')`，跟随用户在设置里的自定义胜负色
   - 英雄头像用 `RoundIcon`（圆形 + 2px 金环）
   - 「标记本人」抄 `search_interface` 标记当前召唤师的做法：中性行底色 + 名字用 `--ThemeColor*`
2. 新增配置项 `cfg.enableDamagePanel`（`Functions` 组，默认 `True`）与 `StyleSheet.DAMAGE_PANEL_WINDOW`
3. 自绘三色堆叠伤害条 `DamageBarWidget`，以及行 / 组 / 图例控件（`app/components/damage_panel.py`）
4. 面板弹窗 + 取数解析 + 右上角定位（`app/view/damage_panel_window.py`）
5. 双主题 QSS（`app/resource/qss/{dark,light}/damage_panel_window.qss`）
6. 接线：`main_window.__onGameStatusChanged` 在 `PreEndOfGame / WaitingForStats / EndOfGame` 阶段触发取数并弹出
7. 设置页加入开关卡片

## 遇到的问题及解决方案

### 1. 两个致命 bug：用真实 LCU 数据才暴露出来

Code review 阶段正好有活着的客户端，reviewer 直接连 LCU 跑了一局真实的 10 人 ARAM，抓到两个用假数据永远发现不了的问题：

- **`teams[].win` 是字符串 `'Win'/'Fail'`，不是布尔**。原写法 `bool(team.get('win'))` 里 `bool('Fail')` 是 `True`，导致**两队都被标成「胜利」**，输的那局也显示我方胜利。
  修法：`isWin()` 兼容字符串与布尔（`'win'/'true'/'1'` → 胜利）。
- **承伤的魔法字段名是 `magicalDamageTaken`，不是 `magicDamageTaken`**。后果不只是魔法承伤显示 0——缺失的那约 35% 会被画成物理伤害，等于给出错误结论。
  修法：候选名列表补上 `magicalDamageTaken`；同时把 `unsplit` 的判定从「三段全为 0」改成「三段之和不足总量的 98%」，任何字段缺失都会退化成中性色单条，而不是把缺口算进物理。

修完后又连真实 LCU 验证了一遍：真实字段确认为 `magicalDamageTaken`，`win` 原始值确认为 `('Win', str)`，解析出的标签正确变成「我方 · 失败 / 敌方 · 胜利」。

### 2. 「我」那一行的高亮是隐形的

`DamageRowWidget` 是普通 `QWidget`，**不设 `WA_StyledBackground` 就不会绘制 qss 背景**，所以 `DamageRowWidget[current=true] { background-color }` 从来没生效过。像素采样验证（普通行 `#f3f3f3` vs 本人行 `#ececec`）后才确认修好。

### 3. 取数失败会连弹错误提示

结算数据不是游戏一结束就立刻可取，所以带重试；但 connector 的 `@retry()` 耗尽重试时会发 `signalBus.lcuApiExceptionRaised`，`main_window` 会弹 `InfoBar` 错误——**一局最多弹 8 次**，与「只记日志不打扰用户」的初衷矛盾。
修法：面板取数期间置一个静默标志，`main_window` 对该面板会调的那 4 个接口让路（其它调用方行为不变）。

### 4. 匹配历史滞后时会弹错对局

`games[0]` 未必是刚打完那局；一旦弹了上一局，`__shownGameId` 还会把正确那局永久挡掉。
修法：优先用 `connector.getGameflowSession()` 的 gameId 作为「刚结束这局」的权威依据，再加一道「结束时间在 15 分钟内」的时效校验。

### 5. 已安装的库版本比 GitHub master 旧

一开始照 GitHub master 源码写了 `Pivot.currentRouteKey()` 与 `Pivot.currentItemChanged`，**实测两者在已安装的 1.5.7 里都不存在**，切换只能靠 `addItem(..., onClick=)`。

### 6. 类名冲突

新控件原本要叫 `.seg`，而伤害条的分段类名已经是 `.seg`——撞名会让每一段被套上 `display:flex; flex:0 0 auto`，**整条直接渲染不出来**。改名为 `.part`。

## 经验总结

1. **依赖库的 API 细节必须内省已安装版本，不能照 master 源码写。** 本次两次踩坑（`currentRouteKey`、`currentItemChanged`）都是这个原因。
2. **外部接口的字段名和类型必须用真实数据探，不能靠记忆推断。** `magicalDamageTaken` 与 `win` 的字符串类型都是只有真实数据才会暴露的。
3. **在能跑的环境里把界面渲染出来截图，比通读代码有效得多。** 本次 `WA_StyledBackground`、侧边 chip 被纵向拉伸、进度条分段的配色与比例，都是渲染截图后才发现的。
4. **纯 `QWidget` 想用 qss 背景必须设 `WA_StyledBackground`**；动态属性变化后要 `unpolish/polish`，且**子控件的后代选择器要单独 polish**。
5. **静默失败最危险。** 三段伤害取不到时不能把总量算成物理伤害；`gameId` 为 `None` 时不能当作「已弹过」。这类地方宁可退化成中性表现，也不给出错误结论。

## 后续优化建议

1. **竞技场的真实小队分组**：目前仅按 `teamId 100/200` 分成两组（8 人），并在该模式下**不声称胜负**、芯片转中性色。真按 `subteamPlacement` 分成 4 队 × 2 人是另一个功能。
2. **设置卡片的英文 i18n**：当前用中文源字符串（与 `gameflow_interface.py` 一致），英文界面下会显示中文。若要英文化，需在 `Seraphine.zh_CN.ts` 加词条并用 `lrelease` 重新编译 `.qm`（本机未安装 `lrelease`）。
3. **置顶做成开关**：目前无条件置顶，可考虑与「对局结束弹面板」并列加一个配置项。
4. **`tools.py:373` 的疑似既有隐患**：`win = stats['win']` 后经 `getMapIconByMapId(mapId, win)` 按真假值选图标。既然 `teams[].win` 实测是字符串，`stats['win']` 也可能同样是字符串——若是，这个地图图标会永远是 victory。**未实测确认**，建议自查。
5. review 中判定「真实数据不可达」而暂未处理的三项：第 3 个及以后的阵营会被丢弃、空阵营仍画失败色芯片、`zip` 在单阵营时会留旧行。
