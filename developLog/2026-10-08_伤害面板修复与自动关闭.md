# 对局伤害面板：修复不弹出 + 二级菜单与自动关闭

## 功能概述

本次包含两件相关的事：

**一、修复「对局结束后伤害面板不弹出」**（上一版 `2026-10-07_对局伤害面板.md` 的功能实际不可用）

**二、设置里的功能选项升级为二级菜单，并支持自动关闭**：新增「弹出后自动关闭」开关与「自动关闭时长（秒）」，**默认开启、15 秒后自动关闭**。

## 实现步骤

### 一、定位「不弹出」

排查完全靠实证，没有靠猜。关键手段是**在应用进程外部取窗口状态**，以及**另起一个进程在同一时刻复现同一套取数逻辑**。

现象（用 Win32 API 直接读应用进程里的面板窗口）：

```
title         = '伤害统计'
GetWindowRect = (1904, 16, 2544, 695)  →  640x679   ← 满数据尺寸，位置正是右上角
EXSTYLE: TOPMOST = True                              ← 置顶代码执行过
STYLE:   VISIBLE = False                             ← 但窗口是隐藏的
ShowWindow(SW_SHOW) 之后 → IsWindowVisible = 1        ← 手动显示立刻成功
```

即：**取数、填数据、定位、置顶全部成功，只有最后的"显示"没生效**；而应用日志里一条记录都没有（因为失败诊断用的是 `logger.warning`，而日志级别是 40/ERROR）。

修掉的问题：

1. **`__shownGameId` 赋值在 `show()` 之前**：中间任何一步抛异常都会被 `except` 吞成不可见的 warning，重试时又因 gameId 相同而直接判定「已弹过」→ 静默永久放弃，留下「有数据、已定位、已置顶、但不可见」的窗口。改为**确认显示成功之后才记账**。
2. **`__closed` 标志在 `closeEvent` 里置位**：用户手动关掉面板是正常操作，却会让面板在本次运行里再也不出现。改为独立的 `__shuttingDown`，只由应用退出路径经 `blockShowing()` 设置。
3. **显示自检只查 Qt 层**：实测症状在 Win32 层（`Qt.isVisible()=True` 而 `IsWindowVisible=False`），只查 Qt 会让自检通过、`__shownGameId` 被置位、自愈失效。改为**两层都查**，并用 `ShowWindow(SW_SHOW)` 兜底。为验证这一条，测试里**人为用 `SW_HIDE` 制造出这个坏状态**，确认能被救回。
4. **失败诊断全部改成 `error` 级**并带上每个候选对局的失败原因 —— 否则「面板没弹」这类问题永远无从查起。

### 二、取数逻辑（这个功能真正的坑）

对局刚结束时拿不到数据，根因是三个叠加的接口行为：

1. 对局刚结束，`gameflow session` 里**已经有** `gameData.gameId` 了，但详情接口 `/lol-match-history/v1/games/{id}` 对该局返回**没有 `participants` 的空壳**。实测那个空壳是一个 `RPC_ERROR` 响应体（`keys=errorCode,httpStatus,implementationDetails,message`）。原实现拿到空壳就 `return None`，然后**拿同一个无效 id 重试 8 次**，从不回退。
2. 匹配历史**列表**接口的每个条目前只含**自己那 1 个 participant**，不能当 10 人数据用；而且索引到这一局有延迟。
3. 本局还没进列表索引时，列表里最近一局就是**上一局** —— 拿它当结果会弹出上一局的数据。

最终逻辑：session 候选优先（权威，只校验 gameId 对得上 + 人数 > 1 + 时长已结算，**时长未结算时直接等下一轮、绝不回退**）；只有 session 拿不到时才回退匹配历史，且回退候选必须**刚刚结束**（`HISTORY_TOLERANCE = 3 分钟`）；重试窗口 24 秒 → **60 秒**以覆盖索引延迟。

### 三、二级菜单与自动关闭

- 新增 `DamagePanelSettingCard(ExpandGroupSettingCard)`（结构照 `AutoAcceptCard`）：标题行放状态摘要，展开区三项 —— 面板总开关、自动关闭开关、时长输入。
- 新增配置 `EnableDamagePanelAutoClose`（默认 `True`）与 `DamagePanelAutoCloseDelay`（`RangeConfigItem`，默认 15，范围 5–300）。
- 面板弹出时读取配置起 `QTimer`，到点 `close()`；设置变化时若面板正显示则**立即重排定时器**。
- 必须配套 `WA_QuitOnClose=False`：主窗口最小化到托盘时，定时器关闭面板会变成「关掉最后一个窗口」从而**退出整个应用**。

## 遇到的问题及解决方案

| 问题 | 原因 | 解决 |
|---|---|---|
| 面板不弹出，且日志无任何记录 | 见上文三点（记账顺序 / `__closed` / 自检只查 Qt 层）+ 诊断级别不可见 | 逐条修复，诊断改 `error` 级并带上下文 |
| 对局刚结束取不到数据 | 详情接口返回 `RPC_ERROR` 空壳，而代码拿同一个 id 死重试 | 候选 + 校验 + 回退 + 60 秒窗口 |
| 可能弹出**上一局的数据** | 回退候选用了 15 分钟宽限，短局（大乱斗 9 分钟）恰好命中 | 回退收紧到 3 分钟；session 候选时长未结算时不回退 |
| `except Exception` 兜不住自定义异常 | `app/lol/exceptions.py` 里 5 个异常**全部继承 `BaseException`** | 改 `except BaseException`，并显式放行 `CancelledError/SystemExit/KeyboardInterrupt` |
| 自动关闭定时器永不启动 | `__showPanel` 的显示自检在「一切正常」时**提前 return**，而定时器调用原本放在函数末尾 | 把武装定时器移到自检之前（**由测试抓出**） |
| 设置项改动后不即时生效 | 定时器只在弹出时读配置 | 连 `ConfigItem.valueChanged`，面板可见时重排 |
| 数值范围两处双写 | `RangeValidator(5,300)` 与 `SpinBox.setRange(5,300)` 各写一遍 | 改用 `RangeConfigItem`，卡片里 `setRange(*cfg.xxx.range)` |

## 经验总结

1. **外部接口的字段名、类型、以及「什么时候才可用」都必须用真实数据探。** `magicalDamageTaken`、`teams[].win` 是字符串、以及「对局刚结束时详情接口返回空壳」这三点，全是只有真实对局才会暴露的。
2. **静默失败最危险，而且很容易自己造出来。** 本次最耗时的两个问题（面板不弹、查不出原因）都源于「异常被吞 + 日志级别过滤」。失败路径一定要用**用户实际会落盘的级别**输出，并带上足够定位的上下文。
3. **日志级别会决定可诊断性。** 本仓库默认 `LogLevel=40`，`logger.warning` 根本不落盘 —— 写诊断日志前先确认目标级别。
4. **判断「窗口有没有真的显示」要查到 Win32 层。** Qt 的 `isVisible()` 与原生 `IsWindowVisible` 可能不一致，只信一层会漏。
5. **「记账」必须放在动作成功之后。** 把「已处理」标记写在动作之前，一旦动作失败，重试就会被自己的标记挡住 —— 这类 bug 的最终表现是「永久静默放弃」。
6. **宁可不弹，也不要弹错。** 回退候选的时效判据必须 fail-closed（时间字段缺失即判为不合格），因为 LCU 的残缺条目恰恰会缺字段。
7. **依赖库的 API 要内省已安装版本**（本次 `ExpandGroupSettingCard` 的标题属性是 `card.titleLabel` 而非 `titleLabel`，`Pivot` 在 1.5.7 里没有 `currentRouteKey`）。
8. **能跑起来验证的，就不要靠读代码下结论。** 本次「人为用 `SW_HIDE` 制造坏状态再确认能自愈」的测试，比读十遍代码更有价值。

## 后续优化建议

1. **竞技场的真实小队分组**：目前仅按 `teamId 100/200` 分成两组（8 人），并在该模式下不声称胜负。真按 `subteamPlacement` 分 4 队是另一个功能。
2. **`PANEL_APIS` 让路机制的固有代价**：面板取数期间（最长约 60 秒），其它调用方对同几个接口的报错提示也会被静默。要彻底解决需按调用来源标记（如 `contextvars`），改动面大于收益，暂留。
3. **i18n**：本机无 `lrelease`，无法编译 `.ts`，因此设置卡片用中文源字符串（与 `gameflow_interface.py` 一致）；英文界面下这些串不会被翻译。有 Qt 工具链的机器可跑 `lupdate/lrelease` 补齐。
4. **自动关闭的默认值**：15 秒按需求设定；10 人 × 三项伤害的阅读量偏紧，可考虑 20–30 秒，或鼠标悬停在面板上时暂停计时。
5. **`tools.py:373` 的疑似既有隐患**：`win = stats['win']` 后续按真假值选地图胜负图标。既然 `teams[].win` 实测是字符串 `'Win'/'Fail'`，此处若也是字符串，图标会永远是 victory。**未实测确认**，建议自查。
6. review 中判定「真实数据不可达」而暂未处理：第 3 个及以后的阵营会被丢弃、空阵营仍画失败色芯片、`zip` 在单阵营时会留旧行。
