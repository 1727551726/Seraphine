# 大乱斗备选池窗口重做（方案 A）

## 功能概述

把原来的 360×480 简单备选池窗口重做为 384×448 的「指挥台」布局，并补齐倒计时、预选抢英雄和备选池同步：

- **固定两排英雄头像高度**（384×448），1–10 个英雄都保持同高，窗口不再随数量长高/抖动。
- 环形倒计时：自绘 + 16ms 计时，平滑推进；深/浅双主题。
- 优先目标：只显示 28px 头像（名字放 tooltip），池内命中时主题色描边。
- 备选池：5 列卡片，支持目标角标、预选角标、busy/lock、空状态。
- **预选抢英雄**：选人阶段左键预选（绿色 3px 方框 + 绿色「预选」角标），右键取消；进入 `FINALIZATION / GAME_STARTING` 立即自动 `benchSwap`；确认阶段内左键直接更换，预选不再生效。
- 修复备选池同步：拿到 `benchChampions` 立即用本地图标路径上屏，图标在后台逐个补；单个图标失败不再拖垮整排卡片。
- 留档一套 HTML 设计预览与实机截图。

## 实现步骤

### 1. 窗口布局

- `WIN_WIDTH = 384`、`WIN_HEIGHT_TWO_ROWS = 448`；标题栏 48→36。
- 结构：英雄卡 88 → 优先目标 28 → 备选池标题 18 + 网格（1 行 84 / 2 行 174）→ 状态行 20；根边距 14/16，间距 12。
- `__updateWindowHeight()` 固定为 448：删除了 358 单行高度和高度变化后的 `adjustPosition()`；0–10 个英雄高度和位置都不变。
- `ChampionCard`：65×84，圆角 6；目标/预选角标；主题色描边；预选用绿色 3px 方框；busy spinner；lock 半透明；卡片按 `championId` 复用，QPixmap 缓存，避免换人时整排头像闪一次。
- `TargetChip`：28×28 纯头像，`setIconPath()` 支持缺图占位后补图；最多平铺 8 个，不再折叠 `+N`。
- `StatusLine`：success / error / warn / info / selected / muted；success 4 秒回落；selected 绿色预选状态。
- `EmptyBench` 呼吸点空状态；`StyleSheet.ARAM_BENCH_WINDOW` + dark/light QSS。

### 2. 环形倒计时

- `RingTimer`：`QPainter.drawArc` + 16ms `QTimer` + `QElapsedTimer`，用 float 进度，不用 `QProgressBar.setValue`（qfluentwidgets 每次 setValue 会重启 150ms 动画，导致一顿一顿）。
- `updateTimer()` 用 `totalTimeInPhase` 作为环形分母，缺失时才退回「本阶段首次观测到的剩余时间」；阶段切换重置 max。
- 接受所有有计时的阶段（`PLANNING / BAN_PICK / FINALIZATION / GAME_STARTING`），不再只认前两个，避免确认阶段时间冻住；`isInfinite` 时停表。
- 本地 16ms 计时只在偏差 >1 秒或阶段切换时重新对表；LCU 每秒一次的更新不会把环拉回去。
- 阶段文案：预选阶段 / 选人阶段 / 确认阶段 / 即将开始；确认阶段提示「等待进入游戏」。
- 倒计时归零只提示一次；≤10 秒的告警不会被 success/error/info/selected 状态吞掉。

### 3. 预选抢英雄

- `preSelectedChampionId` + `_swapToken`；左键设置/切换预选，右键取消；同一张卡再左键不取消。
- 选人阶段：预选后状态行显示「已预选 X · 进入确认阶段自动抢下」。
- `updateTimer()` 检测到阶段切到 `FINALIZATION / GAME_STARTING`：先 `__tryPreGrab()`，再清空预选；确认阶段内左键直接 `benchSwap`，不进入预选。
- 预抢走 `__startBenchSwap(auto=True)`，状态「正在抢下 X…」；失败/成功走原 token 保护；`clearBench` 会作废在飞请求。
- 预选英雄被换走时自动清预选并提示；阶段切换时清掉角标/状态，避免确认阶段残留。

### 4. 备选池同步

原实现的问题不是 `benchChampions` 数据，而是**显示被图标串行 await 卡住**：

- 每次 `champSelectChanged`：
  1. 用本地 `app/resource/game/champion icons/{id}.png` 立即 `updateBenchChampions`，卡片先出现（缺图先显示名字首字）；
  2. `updateTimer()`，此时 FINALIZATION 预抢读到的是本帧卡片；
  3. 再逐个 `await connector.getChampionIcon()` 补真实图标，完成后更新；单个图标失败用本地路径兜底并记错误日志，不再中断整次更新。
- `clearBench()` 从 `__onChampionSelectBegin` 前移到 `__onGameStatusChanged` 的 `ChampSelect` 分支最前面，放在 `getMapSide()` 之前，避免把 await 期间已到达的 `champSelectChanged` 画好的卡片清掉。
- `__onChampionSelectBegin` 用首帧 session 的 timer 先点亮倒计时，并提前显示窗口。
- 窗口可见时即使关掉自动抢选也继续刷新，避免手动换英雄看到冻结数据。

## 遇到的问题及解决方案

| 问题 | 原因 | 解决 |
|---|---|---|
| 倒计时一秒跳一次、有停顿 | `QProgressBar.setValue` 每次都重启 150ms 动画；HTML 预览用宽度布局会触发像素对齐 | 自绘环形 + 16ms 浮点进度；HTML 用 `stroke-dashoffset`/合成层动画 |
| 每秒重对表导致倒退/跳变 | LCU `adjustedTimeLeftInPhase` 约一秒更新一次 | 本地 16ms 连续推进，偏差 >1s 或阶段切换才对表 |
| 进入确认阶段时间冻住 | 只接受 `BAN_PICK / PLANNING` | 接受所有有限阶段；`isInfinite` 才停 |
| 环形比例不对 | 分母用首次观测值 | 优先用 `totalTimeInPhase` |
| 换英雄时所有头像刷新 | 每次重建全部卡片、重新加载 QPixmap | 按 id 复用卡片；列表/顺序不变不动布局；同路径空 pixmap 才重载 |
| 选人阶段备选池空白、确认阶段才出现 | 图标串行 await 全部完成才 `updateBenchChampions`；单个图标异常中断整次更新；`clearBench` 在 `getMapSide` 之后清掉已画卡片 | 本地路径立即上屏；图标逐个补、失败兜底；`clearBench` 前移到 `getMapSide` 之前 |
| 超过 5 个英雄时窗口长高/抖动 | 1 行 358、2 行 448 自适应，并重算位置 | 固定 448，删除单行高度与高度变化的 `adjustPosition` |
| 预选到了确认阶段还显示/误抢 | 预选只在选人阶段；确认阶段要左键直接换 | 阶段切换先抢再清预选；确认阶段左键直接 `benchSwap`；绿框加粗 |
| 预抢在倒计时归零才触发 | 需求是进入确认阶段立即抢 | `updateTimer` 的 `phaseChanged` 触发，放在倒计时归零提前返回之前 |
| 右键取消与左键预选冲突 | 左键原先点击即换 | 左键预选，右键取消；确认阶段左键直接换 |

## 经验总结

1. **不要把「上屏」绑在图标下载上。** 本地路径先画，图标后补；用户先看到卡片比等全部图标完成重要。
2. **单个资源失败不能拖垮整排。** 图标下载要逐个 try/except + 本地兜底，否则一个 404/超时会让整排空白。
3. **`clearBench` 要放在 await 之前。** 否则 await 期间到达的 `champSelectChanged` 已经把卡片画好，随后又被清掉；表现为「选人阶段一直空，确认阶段才出现」。
4. **固定高度是消除窗口抖动最直接的方式。** 自适应高度 + `adjustPosition` 在数量跨行时必然产生位置跳变。
5. **自定义控件不要用 `QProgressBar.setValue` 做高频动画。** qfluentwidgets 的 setValue 会重启内部动画，高频调用反而不平滑。
6. **阶段语义要按客户端阶段做，不要按倒计时做。** 预抢应在进入确认阶段时触发，而不是倒计时归零。
7. **卡片复用比重建更稳。** 复用 `ChampionCard` + 缓存 QPixmap，换人时只增删差异卡片，避免整排刷新。
8. **代码 review 的并发/顺序问题值得修。** 本轮的 begin 快照、timer/备选池顺序、chip 图标回填都是 review 发现的真实问题。

## 后续优化建议

1. **真实对局验证**：当前没有真实大乱斗选人环境，`benchChampions` 的下发时机、LCU 图标下载失败率需要在实机再确认；错误日志已带「获取备选池英雄图标失败」。
2. **设计预览页未同步最终交互**：`index.html` 仍是方案 A 的早期设计稿（1 行 358、优先目标带名字、点击即换），App 已改为固定 448、纯头像 chip、预选/右键取消；后续可把预览页一起同步。
3. **i18n**：新增文案都是中文源字符串，本机无 `lrelease`，英文界面下不会翻译；有 Qt 工具链时可补 `.ts/.qm`。
4. **「自动抢选」开关的总开关语义**：预抢目前按「手动预选即授权」处理，不检查 `enableAramAutoSwap`；若希望开关关闭时预抢也禁用，在阶段触发和确认阶段点击两处各补一行判断即可。
5. **图标缓存清理**：`app/resource/game/champion icons/` 只增不减，长期使用可加按版本清理；当前体积可接受。
